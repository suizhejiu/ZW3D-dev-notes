# ZW3D 二次开发实战笔记

> 用 ZW3D 官方 C/C++ 插件 API 做批量建模的踩坑记录。
>
> 这不是一个插件，而是一份**笔记** + 一个**可复用的代码骨架**。

---

## 这是什么

2026 年 10 月，用 ZW3D WuKong 2027 的插件 API 建了 37 个零件。

过程中遇到十来个「**调用返回成功，但结果不对**」的情况。这些坑官方文档基本没写，
整理出来，供后来者少走弯路。

**所有结论都附了实测数据**（包围盒、体积、错误码），可以自己复现验证。

**核心内容**：

- **10 个官方文档没写的失败场景**
  - `-10000` 的真实含义（草图未激活）
  - `cvxRootExit()` 弹空草图确认框
  - `cvxFileClose()` 不调会假死
  - 编译必须加 `/utf-8`
  - 闭合样条的两个参数
  - 带孔轮廓要用两条闭合曲线
  - **任意平面（含 YZ）不要手填矩阵** ← 本文最有价值的一条
  - `cvxPartMoveTransform` 已废弃但会「假成功」
  - 变量：能建但可能没写进文件
  - `ZwVariableDelete` 会卡死插件

- **参数化的正确做法**
  - `cvxSkAddConsDim` + `cvxDimValMod` 让尺寸引用变量
  - 实测数据：D 从 80 改成 100，体积从 22678.372 跳到 36815.539
  - **限制**：事后改变量不会自动重建，要「每个配置完整重跑一遍」

- **官方资源索引**
  - `api\` 目录里有什么（22 MB CHM + 20 个示例）
  - 20 个示例的导读
  - `DllRegister` 插件注册工具

## 一份坦诚的说明

**这个项目的大部分时间，花在了「把官方界面上的操作，用 API 复现一遍」。**

做完才发现，官方的参数化零件库已经做了同样的事，而且不需要写代码。

**所以它的价值不在「自动化」本身**，而在于：

1. **记录了什么会失败** —— 官方文档只讲函数签名，不讲「什么时候不work」
2. **暴露了官方没覆盖的地方** —— 零件库是交互式的，不能脚本化
3. **一个可复用的骨架** —— 把踩过的坑封装成函数，下次不用再踩

**如果你只想要「建模」，用官方零件库就好。**

**如果你想知道「为什么这样会失败」，这份笔记可能有用。**
